# `backfold` Benchmark & Scientific Integrity Protocol

Every quantitative claim published for `backfold` must follow five non-negotiable rules:

1. **Live Silicon Only (`[LIVE-CPU]`):** Zero analytical projections or unmeasured claims. Every timing table is generated by running `benchmarks/run_benchmarks.py` and `cargo run --release --bin backfold -- bench` on real hardware, capturing CPU model, OS, Rust/Python versions, and git commit SHA.
2. **Exactness Before Speed:** Every benchmarked operation asserts exact mathematical parity (`max_abs_diff <= 1e-10` for Kalman/Ridge/EWMA/Moments/CUSUM; `0.0` duplicate echo error) against an independent naive chronological sequential oracle. Any implementation that diverges fails the benchmark.
3. **Strong Compiled & Ecosystem Opponents:** Benchmark against BOTH real installed Python libraries (`river`, `pandas`, `polars`, `numpy`, `scipy`) AND an optimized `-O3` sequential Rust reference (so speedups measure true algorithmic $O(\log T)$ vs $O(T)$ gains, not merely Rust-vs-Python overhead).
4. **Honest Crossover Disclosure:** Always measure and publish the pure append-only single-pass regime where a plain linear scalar loop beats a persistent tree, alongside the exact $T$ and workload crossover where `backfold` wins.
5. **Independent Adversarial Breaker Audit:** Every release must pass `tests/breaker_audit` covering out-of-order permutations, retractions to empty, `1e12 + N(0,1)` cancellation stress, `cond = 1e10` ill-conditioned matrices, `NaN`/`Inf` rejection, huge timestamp gaps, multi-threaded concurrent fork/merge, and `e-BH` empirical FDR control under null streams.
