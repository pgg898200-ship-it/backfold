# Event-by-event benchmark

Run from the repository root on a POSIX system with a C++17 compiler, zstd, zlib and LZ4.

```sh
make -C bench
build/bench fixtures 7 2048 > results.csv
python3 bench/summarize.py results.csv
```

If the linker has only a versioned LZ4 library, use `make -C bench LZ4_LIB=-l:liblz4.so.1` on Linux. The fallback declaration file targets the stable LZ4 frame ABI. The harness prints compiler and library versions to stderr.

Each input file is an independent ordered stream. Each CR, LF or CRLF blank line terminates a frame, including its separator bytes. A partial final frame passes through unchanged. The driver checks the decoded bytes immediately after **every flush** against the original frame. It terminates on any mismatch. Architecture-independent synthetic cases use MT19937 seed 1701 and cover repeated chat envelopes, alternating text/tool/progress event types, and low-redundancy ASCII payloads. Files under `fixtures/holdout/` report separately. Corpus origin and transformation details live in the [fixture manifest](../fixtures/README.md).

## Baselines

| Configuration | Transmitted data and settings |
| --- | --- |
| raw-sse | Original SSE bytes. The copy path gets the event boundary from the driver. |
| raw-varint | Unsigned LEB128 event length followed by the event. |
| eventfold | Four-byte EFL1 stream magic and every record returned by the public header. The wrapper retains a copy of the last frame independently on each side. |
| lz4-linked | One LZ4 frame with default linked-block settings and `LZ4F_flush` after each input event. |
| zstd-1, zstd-3 | One zstd frame at the specified compression level. Each event uses `ZSTD_e_flush`. |
| zstd-1-small | Level 1, windowLog 11, hashLog 10 and chainLog 10, with the same flush schedule. |
| gzip-1, gzip-6 | One gzip stream at the specified level, 32 KiB window and memLevel 8. Each event uses `Z_SYNC_FLUSH`. |
| gzip-1-small | Level 1, 2 KiB window and memLevel 3. Both sides use the smaller window. |
| ws-deflate-6 | [RFC 7692](https://datatracker.ietf.org/doc/html/rfc7692#section-7.2.1) per-message DEFLATE payload, level 6, context takeover, 32 KiB window and memLevel 8. Each frame strips its 4-byte flush marker and the receiver restores it. The driver supplies message boundaries free of charge. WebSocket headers and masking cost are excluded. |

Wire totals include the initial header for each codec that emits one, including the EventFold magic. Counting stops immediately after the last live flush. End-of-stream trailers, transport overhead, TLS, application framing outside the named codec, handshake, I/O and network delay are excluded. Apart from the separately reported raw length baseline, the harness adds no envelope to any codec. All comparisons preserve SSE event bytes and flush boundaries.

## Reading the output

Each time sample reports thread CPU nanoseconds averaged over all events. The harness warms each direction with one pass, then alternates measurement order across repetitions. Each sample replays the stream from a fresh context as many times as needed to meet the minimum event count. The reported value is the median of those sample means. The pipe-separated columns retain the underlying samples. These are amortized codec costs, not latency percentiles. Reusable scratch buffers, file reads, clock-independent verification, context creation and destruction are outside timing. Work performed lazily by the first codec call is included. The checksum consumes each timed output. The summary reports event-count-weighted means of the individual stream medians. It sums bytes across independently initialized streams.

State columns exclude inputs, caller scratch, allocator overhead and the common harness. EventFold reports the previous-event vector capacity on each side. zstd reports its context sizes at the last event. zlib counts peak live allocation requests plus the stream structure. LZ4's public frame API exposes no equivalent context-size query here, indicated by -1. State metrics measure different allocation interfaces and should be interpreted accordingly. A fixture replay does not measure sockets, browser compatibility, concurrency, tail latency or actual application throughput.

## Checked-in run

The [raw results](results.csv) contain 231 workload/configuration pairs and seven samples per direction per pair. The [summary](summary.csv) is generated by `summarize.py`. The run used an x86-64 Linux environment reporting AMD EPYC 9V74, GCC 14.2.0, zlib 1.3.1, zstd 1.5.7 and LZ4 1.10.0, with the default Makefile flags, 2,048 minimum events per sample, no CPU pinning and the versioned LZ4 linker flag above. Reproduction on a different system can change CPU timings. The uncompressed input bytes and wire bytes provide deterministic regression checks for the listed library versions. The two corpora have different event mixes, and the summary keeps them separate.
